# i18n IT/EN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a full English translation of the openeam.it site, selectable via a flag switcher in the navbar, with Italian staying the default at root URLs and English served under `/en/*`.

**Architecture:** Astro's built-in i18n routing (`prefixDefaultLocale: false`) keeps IT at root and puts EN under `/en`. Shared UI chrome (Nav/Footer/BaseLayout) reads `Astro.currentLocale` and pulls strings from a small dictionary (`src/i18n/ui.ts`). Each page's copy is extracted into an IT/EN-keyed object defined inside a shared template component; a thin `src/pages/...` wrapper (IT) and `src/pages/en/...` wrapper (EN) each render that template with `lang="it"` / `lang="en"`. MDX content collections (industries, case studies) are split into `it/`/`en/` subfolders with matching slugs.

**Tech Stack:** Astro 5 (static output), MDX content collections, no test runner in this repo — verification is `npm run build` plus manual browser checks (there is no unit-test infra to hook into, so no TDD steps are prescribed).

## Global Constraints

- Default locale is `it`, served at root paths (no `/it` prefix). English lives under `/en/*`. (`astro.config.mjs` `i18n.routing.prefixDefaultLocale: false`)
- Every internal `<a href>` inside a lang-aware template must be built through the `getLocalizedPath(lang, path)` helper — never hardcode `/demo`, `/pricing`, etc. without localizing.
- Industries and case-studies MDX entries use the **same slug** in both locale subfolders (e.g. `industries/it/manufacturing.mdx` and `industries/en/manufacturing.mdx`) — the language switcher on dynamic pages relies on this.
- Nav/footer link *labels* that are already English words in the current IT site (e.g. "Platform", "By Industry", "Asset Management", "Privacy Policy") are left untouched — they don't need a translation layer. Only strings that actually differ between IT and EN go into `src/i18n/ui.ts` or a page's local `COPY` object.
- No sitemap.xml, no browser-language auto-detection/redirect, no third locale — out of scope per the approved design (see `docs/superpowers/specs/2026-07-16-i18n-it-en-design.md`).

- [ ] **Step 2: Create the routing/translation helpers**

Create `src/i18n/utils.ts`:

```ts
import { ui, type UiKey } from './ui';

export type Lang = 'it' | 'en';
export const DEFAULT_LANG: Lang = 'it';

/** Reads the locale from a URL's pathname (root = it, /en/* = en). */
export function getLangFromUrl(url: URL): Lang {
  return url.pathname === '/en' || url.pathname.startsWith('/en/') ? 'en' : 'it';
}

/**
 * Given any pathname (with or without an /en prefix) and a target lang,
 * returns the equivalent path in that lang. Assumes it/en share the same
 * slug for a given piece of content.
 */
export function getLocalizedPath(lang: Lang, pathname: string): string {
  const withoutLangPrefix = pathname.replace(/^\/en(?=\/|$)/, '') || '/';
  if (lang === 'en') {
    return withoutLangPrefix === '/' ? '/en' : `/en${withoutLangPrefix}`;
  }
  return withoutLangPrefix;
}

/** Returns a `t(key)` lookup into the shared ui.ts dictionary for the given lang. */
export function useTranslations(lang: Lang) {
  return function t(key: UiKey): string {
    return ui[lang][key] ?? ui[DEFAULT_LANG][key];
  };
}
```

```astro
<script>
  import emailjs from '@emailjs/browser';

  interface Messages {
    firstName: string;
    lastName: string;
    company: string;
    role: string;
    email: string;
    consent: string;
    configMissing: string;
    sending: string;
    success: string;
    error: string;
  }

  const SERVICE_ID = import.meta.env.PUBLIC_EMAILJS_SERVICE_ID;
  const TEMPLATE_ID = import.meta.env.PUBLIC_EMAILJS_TEMPLATE_ID;
  const PUBLIC_KEY = import.meta.env.PUBLIC_EMAILJS_PUBLIC_KEY;

  const form = document.querySelector<HTMLFormElement>('[data-demo-form]');
  const statusEl = form?.querySelector<HTMLElement>('[data-status]');
  const msgs: Messages = JSON.parse(form?.dataset.msgs ?? '{}');

  function setError(field: Element | null, msg: string) {
    if (!field) return;
    const wrap = field.closest('.field');
    wrap?.toggleAttribute('data-invalid', !!msg);
    const err = wrap?.querySelector('[data-err]');
    if (err) err.textContent = msg;
  }

  function validate(): boolean {
    if (!form) return false;
    let ok = true;
    const required: [string, string][] = [
      ['nome', msgs.firstName],
      ['cognome', msgs.lastName],
      ['azienda', msgs.company],
      ['ruolo', msgs.role],
    ];
    for (const [name, msg] of required) {
      const el = form.elements.namedItem(name) as HTMLInputElement | null;
      const bad = !el?.value.trim();
      setError(el, bad ? msg : '');
      if (bad) ok = false;
    }
    const email = form.elements.namedItem('email') as HTMLInputElement | null;
    const emailOk = !!email && /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email.value.trim());
    setError(email, emailOk ? '' : msgs.email);
    if (!emailOk) ok = false;

    const consent = form.elements.namedItem('consenso') as HTMLInputElement | null;
    if (!consent?.checked) {
      showStatus(msgs.consent, 'err');
      ok = false;
    }
    return ok;
  }

  function showStatus(msg: string, tone: 'ok' | 'err') {
    if (!statusEl) return;
    statusEl.hidden = false;
    statusEl.textContent = msg;
    statusEl.setAttribute('data-tone', tone);
  }

  form?.addEventListener('submit', async (e) => {
    e.preventDefault();
    if (statusEl) statusEl.hidden = true;
    if (!validate()) return;

    const submit = form.querySelector<HTMLButtonElement>('[type="submit"]');
    if (!SERVICE_ID || !TEMPLATE_ID || !PUBLIC_KEY) {
      showStatus(msgs.configMissing, 'err');
      return;
    }

    submit?.setAttribute('disabled', 'true');
    const original = submit?.textContent;
    if (submit) submit.textContent = msgs.sending;

    try {
      await emailjs.sendForm(SERVICE_ID, TEMPLATE_ID, form, { publicKey: PUBLIC_KEY });
      form.reset();
      showStatus(msgs.success, 'ok');
    } catch (err) {
      console.error('[EmailJS]', err);
      showStatus(msgs.error, 'err');
    } finally {
      submit?.removeAttribute('disabled');
      if (submit && original) submit.textContent = original;
    }
  });
</script>
```

Note: the messages reach the client script via a `data-msgs={JSON.stringify(t.messages)}` attribute on the `<form>` (read back with `JSON.parse(form.dataset.msgs)`), NOT via `define:vars` — `define:vars` forces the script to run as a plain non-module script, which is incompatible with the `import emailjs from '@emailjs/browser'` statement this script needs. The data-attribute approach keeps the script a normal TypeScript module, unchanged from the original file's shape aside from the `msgs` lookup and the translated strings.
